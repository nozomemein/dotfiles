# Write Like Me

論理や構成だけではなく、文章の呼吸を本人へ寄せる。
決まり文句を真似るのではなく、文の長短、間の取り方、語尾、率直さを再現する。

## 書き方の基準を選ぶ

必ず[writing-profile.md](references/writing-profile.md)を読む。
さらに本人が書いた文章が入力にあれば、次の順で優先する。

1. 今回提示された本人の文章
2. 本人による書き直しやレビュー指摘
3. writing profile
4. 本人が明示的に採用した過去の出力

AIが生成した文章だけを根拠に、本人の書き方を学習しない。
本人が示していない意見、感情、経験は作らない。

## 構成と文体を分ける

`refine-tech-document`は論理、構成、冗長性を整える。
このskillは、その後にリズムと温度を戻す。

両方を使う場合は次の順にする。

1. `refine-tech-document`で論理と構成を整える
2. `write-like-me`で文章の調子を本人へ寄せる
3. 調子を整えたことで主張や事実が変わっていないか確認する

書き方だけを求められた場合は、見出し、段落順、主張を勝手に組み替えない。

## 下書きを溜めてから組む

整った文をいきなり並べ始めると、等間隔で平板になる。
先に素材を出し切り、あとから組む。

1. 言いたいことを、順序も文体も気にせず全部出す
2. 出し終えてから捨てる。出しながら捨てない
3. 残った素材だけで組み立てる

書き通す間は直さない。
一文ずつ整えると文長の波が消え、同じ速さの文が続く。
直すのは最後まで書き終えてから。

分量の見当がついている場合は、そこで止める。
まだ書ける気がしても足さない。
足りない分を伸ばすほうが、余った分を削るより形が残る。

言い回しを、置く前に捨てない。
本人が使いそうな表現ほど、整える過程で最初に消える。

表現は発明しない。
本人が実際に使った素材を組み替えて作る。

## 内部でリズムを取る

書く前に、次の5点だけを内部で決める。
ユーザーから求められない限り、この分析は出力しない。

- 段落の拍: 一つの考えを何文で置くか
- 文長の波: 短文と中程度の文をどう交ぜるか
- 間: どこで改行や空行を入れるか
- 語尾: 断定、依頼、問いかけ、余韻をどう配るか
- 温度: 媒体に対して、どこまでくだけるか

## リズムを作る

- 同じ長さの文を並べ続けない
- 情報量の多い文の後に、短い文を置いて着地させる
- 一段落に一つの動きを置き、話が切り替わる場所で空行を入れる
- 接続詞で論理を説明しすぎず、文の順序で読ませる
- 同じ語尾を三回以上続けない
- 読点は文法だけでなく、声に出したときの息継ぎで置く
- 強調したい一文は短くする。ただし決め台詞にはしない

文字数や短文率を機械的なルールにしない。
整いすぎた等間隔の文章は、本人らしさではなくテンプレートになる。

## 温度を合わせる

媒体に合わせて、本人らしさの出し方だけを変える。

| 媒体 | 温度 |
| --- | --- |
| チャット、近い相手への依頼 | 近め。問いかけや少しくだけた語尾を残す |
| 部署をまたぐ依頼、周知 | 敬体。丁寧さは語尾だけに置き、範囲と相手の裁量を明示する |
| レビュー | 率直。問題、理由、望む方向を短くつなぐ |
| 技術文書、設計書 | 落ち着いた常体。短文と中程度の文の波は残す |
| PR description | 低い温度で具体的に書く。飾らない |
| 社外向け文章 | 距離を一段置く。テンポは残し、口語だけ抑える |

礼儀を減らすのではなく、儀礼的な前置きを減らす。
断定を弱めるためだけの長い敬語や曖昧語を足さない。

## 本人らしさを誇張しない

- `要は`、`なので`、`〜と思う`などを口癖として毎段落へ入れない
- 誤字、変換ミス、不自然な句読点を文体として再現しない
- `かなー`、`よねー`、`↑`のような会話上の記号を技術文書へ持ち込まない
- すべてを短文へ分解しない
- 率直さを攻撃性へ変えない
- 本人らしく見せるために、新しい主張や評価を足さない
- 文章を磨きすぎて、自然な揺れや話し手の距離を消さない

## 仕上げる

声に出して一度読む。
次のどれかが起きたら直す。

- 同じ速さの文が続き、平板に聞こえる
- 接続詞が多く、説明口調に聞こえる
- 語尾が揃いすぎて、生成文に聞こえる
- 口語を足しすぎて、本人の物真似に聞こえる
- きれいだが、本人が実際には言わない表現になっている

通常は本文だけを返す。
書き方の分析や変更点は、求められた場合だけ短く添える。
